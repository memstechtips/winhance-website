Autounattend.xml Settings

What Winhance writes into autounattend.xml: architecture, edition and key, Windows 11 checks, disk layout, accounts, setup screens and your own scripts.

Pick options in the window above. Winhance writes them into the answer file, never to this PC.

These are the settings on the Unattend page, which unlocks in Builder mode when you pick the Autounattend target. Each one is written into autounattend.xml when you save the file. Nothing is read from this PC, so the tables show where in the answer file each value goes.

Technical Details

Each setting below lists exactly what Winhance reads and writes: registry values, scheduled tasks, power settings and scripts, with the recommended value and the Windows default marked. It is the same table the app shows when you turn on Technical Details in the View menu.

Processor architecture

The processor types the file installs on. Winhance writes each part of the file once for every architecture you tick, so one file can cover x64, ARM64 and x86 PCs.

Edition and product key

The edition Setup installs and the key it uses to choose it. Let Setup ask, pick an edition, enter your own key, or use the key stored in the PC's firmware. The built-in keys choose an edition without activating Windows; your own key does both.

Windows edition

Which edition Setup installs. The edition has to be on the installation media, or Setup asks you to pick one anyway. These keys tell Setup which edition to install. They do not activate Windows, so you still need your own licence afterwards.

Windows 11 requirements

Setup's checks for TPM 2.0, Secure Boot, and the minimum RAM, storage, CPU and disk. Turn them off to install Windows 11 on a PC that fails them. The POPCNT CPU requirement added in 24H2 cannot be skipped.

Disk and partitions

Whether Setup asks where to install Windows, or wipes a disk and partitions it for UEFI or BIOS by itself. The partition screen is the one Setup screen a file cannot simply hide, so a layout here is what makes the install run with nothing to click. Wiping erases the whole disk you name, with no undo.

Disk setup

The one Setup screen a file cannot hide. Pick a layout and Setup wipes the disk below, makes the partitions Windows wants, and installs with nothing to click. Everything on that disk is erased, with no undo. Pick UEFI unless the PC only boots the older way.

Accounts

How the first account is created: a local account, a Microsoft account, or accounts the file makes before the first sign-in. Each account you add has a name, display name, group and password, and one administrator can sign in automatically once. When the file makes the accounts, you also choose whether Setup stays online while it works.

Account at setup

How the first account is created. A local account keeps Setup offline; a Microsoft account uses the normal online sign-in.

User folders location

Where each account's Desktop, Documents, Downloads, Music, Pictures and Videos folders go, for example D:\Users. Every account gets its own folder inside it, such as D:\Users\Name\Documents, the first time it signs in. Leave it empty to keep them in C:\Users. If the new PC has no such drive, the folders stay where they are.

                if ($drive -and (Test-Path -LiteralPath $drive)) {
                    $key = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders'
                    $folders = [ordered]@{ 'Desktop' = 'Desktop'; 'Personal' = 'Documents'; '{374DE290-123F-4565-9164-39C4925E467B}' = 'Downloads'; 'My Music' = 'Music'; 'My Pictures' = 'Pictures'; 'My Video' = 'Videos' }
                    foreach ($name in $folders.Keys) {
                        $target = Join-Path $root $folders[$name]
                        $current = [Environment]::ExpandEnvironmentVariables([string](Get-ItemProperty -Path $key -Name $name -ErrorAction SilentlyContinue).$name)
                        New-Item -Path $target -ItemType Directory -Force | Out-Null
                        if ($current -and $current -ne $target -and (Test-Path -LiteralPath $current)) {
                            Get-ChildItem -LiteralPath $current -Force | Move-Item -Destination $target -Force -ErrorAction SilentlyContinue
                        }
                        Set-ItemProperty -Path $key -Name $name -Value $target -Type ExpandString
                    }
                } else {
                    Write-Log "User folders left in place: $base is not on a drive this PC has" "WARNING"
                }

General

What Setup adds to the new PC: .NET Framework 3.5 from the installation media, and Winhance itself, either as an Install Winhance shortcut on every new account's desktop or installed automatically after setup. Winhance then installs the External Software apps you checked, and deletes their installers afterwards unless you turn that off.

.NET Framework 3.5

Installs .NET Framework 3.5 from the installation media during setup, so older apps that need it work without a download.

Your own scripts

Scripts of your own that run once on the new PC. System-wide scripts run as the system while Windows finishes setting up; per-user scripts run for each person at their first sign-in, as that person. Each one can be PowerShell, a command script, a batch file or a registry file, and Winhance carries it in the answer file exactly as you typed it.

Your system-wide script

Scripts of your own that run once on the new PC, as the system, while Windows finishes setting up. Pick PowerShell, a command script, a batch file or a registry file for each one. Winhance carries each script exactly as you typed it and logs what it did.
