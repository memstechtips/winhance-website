Autounattend.xml Settings

Every setting below is written into autounattend.xml when you build the file. Nothing here is read from this PC, so the tables show the answer-file pass, component and path each value lands in instead of a registry key.

Technical Details

Every setting below shows exactly what Winhance reads and writes: registry values, scheduled tasks, power settings and scripts, with the recommended value and the Windows default marked. This is the same table the app shows under each setting's Technical Details.

Processor architecture

Which processor architectures the file covers. Every component in the file is written once per architecture you tick, so one file can install on x64, ARM64 and x86 PCs.

x64

Intel and AMD PCs, which is most of them. Tick every architecture this file should install on; one file can cover all three.

Windows 11 requirements

Setup's checks for TPM 2.0, Secure Boot and the RAM, storage, CPU and disk minimums. Turning them off lets Setup install on a PC that fails them.

Accounts

How the first account is created, and the local accounts Setup makes before the first sign-in. In Winhance each account you add also carries a display name, a group, a password and the sign-in options; the part that is the same on every PC, and so the part documented here, is the name rule below.

Account at setup

How the first account is created. A local account keeps Setup offline; a Microsoft account uses the normal online sign-in.

General

What Setup adds once Windows is installed: .NET Framework 3.5 from the installation media, and an Install Winhance shortcut on the desktop of every new account.

.NET Framework 3.5

Installs .NET Framework 3.5 from the installation media during setup, so older apps that need it work without a download.
