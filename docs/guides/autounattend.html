Answer file setup

Build an autounattend.xml with Builder mode, put it on your installation media, and know what Windows does with it from Setup to the first sign-in.

An answer file is an autounattend.xml that Windows Setup reads from the root of the installation media. It answers Setup's questions so the install runs without stopping, and Winhance uses it to carry your apps, settings and scripts onto the new PC. Nothing you choose here changes the PC you are using.

If you only want the reference for each setting, see Autounattend.xml settings.

Builder mode

Builder mode lets you make a config or an answer file from the settings in the app without applying anything to this PC. While you are in it, the normal app actions are turned off.

  1. Enter Builder mode

    Switch the Winhance Mode selector in the title bar to Builder. The first time, a short introduction explains the mode; tick Don't show this again to skip it next time.

  2. Choose a starting point

    The Start Builder from... window offers four starting points:

    • The current state of this machine: every setting starts at this PC's current value.
    • All Winhance recommended settings
    • All Windows default settings
    • A saved Winhance config or answer file: reopens a .winhance file or an answer file Winhance made (see reopen an answer file).

  3. Pick the Autounattend target

    The Builder bar at the top of the window has two targets, Config and Autounattend. Pick Autounattend. This unlocks the Unattend page in the left navigation, which holds the choices that only exist in an answer file.

  4. Pick the target Windows

    The dropdown on the Builder bar sets the Windows release the file is for: Windows 11 26H2, 25H2, 24H2, 23H2, Windows 10 22H2, or All Windows versions. It starts at the newest release. Only settings that exist on the release you pick are shown and saved. If you switch to a release that lacks some settings you already set, Winhance warns you; they are left out of the file but come back if you switch back.

    Tick Show settings for other hardware to also see settings this PC cannot have, such as battery settings on a desktop.

  5. Make your choices

    Work through the pages:

    • Unattend: the answer-file settings, such as edition, accounts, disk layout and setup screens. The Included from other features card at the top counts what the other pages add to the file.
    • Software & Apps: checked Windows apps are removed while Windows installs. Checked External Software apps are installed for everyone on the new PC after setup, by Winhance.
    • Optimize and Customize: every setting card has a tick that decides whether it goes in the file. Use Include All Settings or Exclude All Settings under Quick Actions to change a whole page.

  6. Save

    Click Save autounattend.xml on the Builder bar. The file must be named autounattend.xml, because that is the only name Setup looks for. Winhance checks that the generated script and XML are valid before it writes the file.

You can save both kinds of file in one session: save a config with the Config target, then switch to Autounattend and save the answer file. Cancel on the Builder bar leaves Builder mode and discards your choices.

Building media? Start from WIMUtil instead

The Set up the answer file button in WIMUtil opens the same Builder session, sets the target Windows to the build on your ISO, and writes the file straight onto the media. It also adds two options this page does not have on its own: putting the External Software installers on the ISO so they install offline, and adding Your own installers.

What the answer file covers

The Unattend page groups its settings like this. Each one is documented on the Autounattend.xml settings page.

  • Processor architecture: x64, ARM64 and x86. One file can cover all three.
  • Edition and product key: ask during Setup, pick an edition, use your own key, or use the key stored in the PC's firmware. The built-in keys choose an edition but do not activate Windows.
  • Windows 11 requirements: turn off Setup's TPM, Secure Boot, CPU, RAM, storage and disk checks.
  • Disk and partitions: let Setup ask, or wipe a disk and partition it for UEFI or BIOS with nothing to click. Wiping erases that disk, so check the disk number first.
  • Accounts: a local account, a Microsoft account, or accounts the file creates for you, and whether Setup stays online.
  • Setup screens: Setup language, the licence, OEM registration and network pages, the privacy questions, and the computer name.
  • General: .NET Framework 3.5, how Winhance gets onto the new PC, and whether app installers are deleted after they run.
  • Your own scripts: PowerShell, command, batch or registry scripts that run once, either system-wide or for each person who signs in.

On top of that, the file carries the Windows apps to remove, the External Software apps to install, and every included Optimize and Customize setting.

Treat the file as private

If the file creates accounts with passwords, it contains those passwords. Obscure the password in the file stores them as base64, which hides them from a glance but not from anyone who decodes them.

Put it on installation media

  • With WIMUtil (recommended). Generate the file in step 2 of WIMUtil, add drivers if you want them, then create an ISO or write a USB drive. This is the only way to include drivers and offline installers.
  • On an existing Windows USB drive. Copy your saved autounattend.xml to the root of a USB drive that already holds Windows installation files. Setup picks it up from there.

What happens during installation

  1. Setup starts

    Setup reads the file and applies what you chose for the setup language, edition, hardware checks and disk. Any screen the file does not answer still appears.

  2. Windows prepares the PC

    Before the first setup screens, still running as the system, the file unpacks Winhance's scripts to C:\ProgramData\Winhance\Unattend\Scripts and runs Winhancements.ps1. It installs any drivers WIMUtil added, removes the Windows apps you checked, applies the machine-wide settings, runs your system-wide scripts, and registers the scheduled tasks below.

  3. The setup screens

    You see only the screens the file left open, for example the account screens if the file does not create the accounts. A local account keeps Setup offline. If you chose Disconnect until Setup finishes, the network comes back at the first sign-in.

  4. The first sign-in

    A scheduled task named WinhanceUserCustomizations runs at every sign-in. The first time an account signs in, it applies the per-user settings (theme, taskbar, Start menu, Explorer and the rest) and that account's per-user scripts, then restarts the PC about 20 seconds later so they take effect. It marks the account as done in HKCU\Software\Winhance\UserCustomizationsApplied, so later sign-ins skip it. Accounts created later get the same treatment at their own first sign-in.

  5. After the restart

    What happens next depends on Winhance on the new PC. With Desktop shortcut, every new account gets an Install Winhance shortcut that installs Winhance and then the External Software apps you checked. With Install automatically after setup, that happens on its own at the next sign-in, and retries at the following sign-in if it fails. With Don't add, nothing is installed.

On the new PC

WhatWhere
Winhance scripts from the answer fileC:\ProgramData\Winhance\Unattend\Scripts
Log of what the script didC:\ProgramData\Winhance\Unattend\Logs\Winhancements.txt
App removal scriptsC:\ProgramData\Winhance\Scripts
Scheduled tasksThe Winhance folder in Task Scheduler. The removal tasks run the removal scripts again at sign-in or startup, so removed apps stay removed after Windows updates.
Setup's copy of the answer fileC:\Windows\Panther\unattend.xml

To apply an account's per-user settings again, delete the UserCustomizationsApplied value under HKCU\Software\Winhance and sign out and back in.

Some settings are written as Windows policies, so Windows Settings may show "Some of these settings are managed by your organization". That is expected. Change them back with Winhance.

Reopen an answer file

Every answer file Winhance makes carries a copy of your choices, the target Windows and, from WIMUtil, the media choices. To change one, enter Builder mode, choose A saved Winhance config or answer file and pick the autounattend.xml. Builder opens with the Autounattend target and everything set the way you left it.

Builder cannot open an answer file another tool made, or one from an older Winhance version that did not store its choices. Generate that file again with the current version.
